# Manga PSD Studio

تطبيق ويب محلي مستقل لترجمة صفحات المانجا **الإنجليزية واليابانية إلى العربية**، ثم تصدير
ملف **PSD** يحتوي على:

- خلفية منظفة من النص الأصلي (Inpainting).
- طبقة نص عربية قابلة للتعديل لكل فقاعة.
- خط عربي محدد بالاسم داخل طبقة PSD.
- إضافة خطوط مخصصة من جهازك (TTF / OTF / WOFF / WOFF2) وحفظها محليًا في المتصفح.
- استيراد مجلد كامل أو عدة صور، وترتيب الصفحات تلقائيًا، ثم ترجمة كل الصفحات
  وتركيب PSD لها بضغطة واحدة عبر **ترجمة الكل**.
- **OCR محلي أولًا** للإنجليزية واليابانية (بما فيها النص العمودي واتجاه القراءة
  من اليمين إلى اليسار) عبر ONNX Runtime Web. لا تُرسل صورة الصفحة إلى Gemini
  عندما ينجح OCR.
- **ترجمة نصية فقط** مع Smart Batch: افتراضيًا 4 صفحات لكل طلب، مع تقسيم تلقائي
  حسب ميزانية التوكنات وعدد الفقرات.
- **معرّفات ثابتة** مثل `p001_b003` ورد JSON مرتبط بالمعرّف، مع التحقق من
  المفقود والمكرر وغير المتوقع بدل الاعتماد على ترتيب المصفوفة.
- **إدارة طلبات** بحد تزامن وRPM/TPM اختياريين، إعادة محاولة مع تراجع أسي
  وjitter، احترام `Retry-After`، وإيقاف مؤقت عند استنفاد الحصة اليومية.
- **ذاكرة ترجمة IndexedDB** تُعيد استخدام النتائج غير المتغيرة، وتُحفظ بعد كل
  دفعة ناجحة؛ تعديل فقاعة واحدة لا يلغي ترجمات الصفحة.
- **Vision اختياري** فقط: إما صراحة من الإعدادات، أو كبديل لفقرات فشل OCR عند
  تفعيل الخيار. لا يعمل تلقائيًا بشكل افتراضي.
- محرر صناديق يدوي على الصورة: إضافة صندوق فات من الكشف، تحريك، تغيير الحجم، حذف،
  وتحرير النص الأصلي والترجمة لكل صندوق.
- حفظ تلقائي للمشروع في IndexedDB، وتصدير/استيراد مشروع كامل كملف `.mpsproj`.
- طبقة معاينة نقطية اختيارية تضمن ظهور العربية بدقة المتصفح حتى لو اختلف تشكيل
  النص داخل محرك PSD.

التطبيق يعمل بالكامل في المتصفح. الصفحات لا تُرفع إلى خادم خاص بهذا المشروع. في
وضع النص (الافتراضي) تُرسل **النصوص المستخرجة فقط** إلى Gemini، وليس الصور. في وضع
Vision الصريح تُرسل صورة الصفحة إلى المزود المختار. في الوضع اليدوي لا يُرسل شيء.

> هذا المشروع منفصل عن إضافة Libre Manga Translator، ويعيد استخدام وحدات AGPL منها.

## البدء السريع

```bash
cd D:\B\777\manga-psd-studio
npm install
npm run dev
```

افتح `http://127.0.0.1:5173/` في Chrome أو Edge حديث.

1. أضف الصفحات: اختر عدة صور، أو اضغط **اختيار مجلد** لاستيراد مجلد كامل، أو أفلت
   المجلد في منطقة الإضافة (PNG / JPG / WebP / GIF / AVIF). تُرتّب الصفحات تلقائيًا
   حسب اسم الملف.
2. اختر لغة المصدر ومحرك الترجمة من لوحة الإعدادات.
3. اختر خط النص من الإعدادات، أو أضف خطًا مخصصًا من قسم **خطوط مخصصة**.
4. اضغط **ترجمة الكل** لتحليل كل الصفحات وترجمتها وتركيب PSD لها دفعة واحدة، أو
   **تحليل الكل** إذا أردت التحليل والترجمة دون تركيب PSD ثم مراجعة الترجمات قبل التركيب.
5. راجع النص الأصلي والترجمة في الجدول وعدّل ما تريد.
6. إن فات الكشف صندوقًا أو أخطأ في حدوده، فعّل **تحرير الصناديق** من لوحة المعاينة.
7. إذا استخدمت **تحليل الكل** فقط، اضغط **تركيب وتحديث PSD** للصفحة الحالية أو
   **ترجمة الكل** لتركيب كل الصفحات. ثم اضغط **تنزيل PSD** للصفحة الحالية أو
   اختر صيغة التصدير (**PSD** أو **PNG** أو كليهما)، ثم اضغط **تصدير جميع الصفحات (ZIP)**
   لتنزيل الملفات في حزمة مضغوطة واحدة.

> **مجلد كامل بضغطة واحدة:** بعد اختيار المجلد، اضغط **ترجمة الكل** فقط. سيعالج
> التطبيق الصفحات بالترتيب ويحدّث حالة كل صفحة، دون الحاجة لفتح كل صفحة وتشغيلها يدويًا.

المشروع يُحفظ تلقائيًا في هذا المتصفح. استخدم **حفظ الآن** للكتابة الفورية، و**تصدير
المشروع** لإنشاء ملف `.mpsproj` يمكن استيراده لاحقًا أو نقله إلى متصفح آخر.

أول تحليل قد يستغرق وقتًا لأن المتصفح ينزّل موديل كشف النص. أول تركيب بجودة LaMa
ينزّل موديل التنظيف أيضًا. بعد ذلك تُستخدم النسخ المخزنة في `CacheStorage`.

## المتطلبات

- Node.js 20.19 أو أحدث (يُنصح بـ 22 LTS؛ تم الاختبار مع Node 26).
- npm.
- متصفح Chromium حديث (Chrome / Edge / Brave). Firefox قد يعمل لكن لم يُختبر.
- اتصال بالإنترنت في أول تشغيل لتنزيل الموديلات، إلا إذا كانت مخزنة مسبقًا.
- مساحة تخزين للموديلات: Comic Text Detector ~95 MB، LaMa ~207 MB، RT-DETR ~11 MB،
  OCR الياباني ~21 MB، OCR الإنجليزي ~8 MB.
- ذاكرة كافية: الصفحات الكبيرة + LaMa تحتاج عدة مئات من الميغابايت من RAM.

التطبيق يستخدم ONNX Runtime Web على WASM بخيط واحد افتراضيًا. هذا أبطأ من GPU لكنه
أكثر ثباتًا عبر المتصفحات والاستضافات. OCR يعمل محليًا بالكامل؛ الموديلات تُنزّل مرة
واحدة وتُخزّن في `CacheStorage`.

## إعداد الترجمة

### 1) Gemini نصي + OCR محلي (الافتراضي، موصى به)

1. احصل على مفتاح من Google AI Studio.
2. في الإعدادات: **محرك الترجمة = Gemini — OCR محلي + ترجمة نصية**.
3. الصق المفتاح. الموديل الافتراضي `gemini-2.5-flash-lite` (أرخص وأسرع للنصوص)،
   ويمكنك تغييره إلى `gemini-2.5-flash` أو `gemini-2.5-pro` أو أي موديل متاح.
4. اختر **طريقة Gemini = نص فقط**.
5. اختر لغة المصدر: اليابانية أو الإنجليزية أو كشف تلقائي.

المفتاح يُحفظ في `localStorage` داخل هذا المتصفح فقط، ولا يُضمّن في ملف المشروع.
لا ترفع نسخة عامة من التطبيق ومفاتيحك بداخلها.

### 2) Gemini Vision (اختياري)

اختر **طريقة Gemini = Vision** فقط إذا أردت إرسال صورة الصفحة بدل النص المستخرج.
هذا يستهلك توكنات أكثر ويرسل الصور إلى Google، لكنه مفيد لصفحات يصعب على OCR
قراءتها. يمكن أيضًا تفعيل **استخدام Vision تلقائيًا للفقرات التي فشل OCR في قراءتها**؛
حينها تُرسل صناديق الفشل فقط، وليس الصفحة كاملة.

### 3) OpenAI-compatible Vision (محلي أو سحابي)

يدعم أي خادم يقبل صيغة OpenAI Chat Completions مع `image_url`، مثل:

- **Ollama** محليًا:
  ```bash
  ollama pull qwen2.5vl:7b
  ```
  ثم:
  - Base URL: `http://127.0.0.1:11434/v1`
  - Model: `qwen2.5vl:7b`
  - API key: اتركه فارغًا.
  - إذا منع Ollama طلبات المتصفح، شغّله مع:
    ```powershell
    $env:OLLAMA_ORIGINS="http://127.0.0.1:5173"
    ollama serve
    ```
- **LM Studio**: شغّل Local Server، ثم Base URL مثل `http://127.0.0.1:1234/v1`.
- **OpenAI**: `https://api.openai.com/v1` + مفتاح + موديل vision.

يجب أن يدعم الموديل الصور فعلًا. الموديلات النصية فقط ستعيد أخطاء أو ترجمة بلا قراءة
للصفحة.

### 4) الوضع اليدوي

يُستخدم للكشف وOCR المحلي دون أي API. بعد التحليل اكتب الترجمة العربية في الجدول،
ثم اضغط **تركيب وتحديث PSD**. مناسب إذا كنت تريد ترجمة بنفسك أو اختبار الكشف
والتنظيف. لا تُرسل أي بيانات إلى مزود خارجي.

## OCR المحلي وSmart Batch

### OCR

- **اليابانية:** `fumetodev/PP-OCRv6_small_rec_manga_ONNX` (~21 MB، Apache-2.0).
- **الإنجليزية:** `monkt/paddleocr-onnx` `languages/english/rec.onnx` (~8 MB، Apache-2.0).
- يفصل OCR كل صندوق إلى سطور/أعمدة، ويعيد ترتيب الأعمدة اليابانية من اليمين إلى
  اليسار، ويدوّر العمود الرأسي قبل التعرف عليه.
- إذا فشل OCR في صندوق، يبقى الصندوق في المشروع مع `sourceText` فارغ وقائمة
  `ocrFailedBoxes`. يمكنك الكتابة يدويًا أو تفعيل Vision للفشل فقط.
- لا يُرسل أي شيء إلى Gemini عندما ينجح OCR ويوجد نص كافٍ للترجمة.

### Smart Batch

| الإعداد | الافتراضي | المعنى |
|---|---:|---|
| Smart Batch | مفعّل | تجميع عدة صفحات في طلب واحد |
| صفحات/دفعة | 4 | الحد الأقصى لعدد الصفحات في الطلب |
| ميزانية التوكنات | 12,000 | تقسيم الدفعة تلقائيًا إذا تجاوزت التقدير |
| طلبات متزامنة | 1 | عدد الطلبات المتوازية |
| RPM / TPM | 0 | 0 = بلا حد محلي؛ لا توجد أرقام مجانية مبرمجة |
| إعادة المحاولة | 4 | مع تراجع أسي وjitter |
| ذاكرة الترجمة | مفعّلة | IndexedDB لإعادة استخدام النتائج |
| Vision عند فشل OCR | متوقف | لا يُرسل أي صورة تلقائيًا |

- تُبنى الدفعات من معرّفات ثابتة `pNNN_bNNN` وليس من ترتيب المصفوفة.
- عند تجاوز الميزانية تُقسَّم الدفعة مع الحفاظ على ترتيب القراءة.
- إذا أعاد Gemini معرّفات ناقصة أو مكررة أو غير متوقعة، تُحفظ الترجمات الصحيحة
  وتُعاد محاولة **المعرّفات الناقصة فقط** بسياق مصغّر.
- إذا فشلت دفعة واحدة لا تُعاد الصفحات الأربع؛ تُستأنف الدفعات المتبقية فقط.
- **متوقع لـ 30 صفحة × 18 فقاعة:** 8 طلبات عند 4 صفحات/دفعة (72 فقاعة لكل طلب)
  إذا لم تتجاوز الميزانية. مع النص الطويل قد يزيد العدد بسبب التقسيم التلقائي.
- التقدير المحلي للتوكنات ليس فاتورة؛ تُعرض التوكنات الفعلية من `usageMetadata`
  بعد كل طلب. خيار `countTokens` يضيف طلبًا صغيرًا لكل دفعة عند تفعيله.
- لا يدوّر التطبيق مفاتيح API ولا يحاول تجاوز الحدود. عند استنفاد الحصة اليومية
  يتوقف مؤقتًا، ويمكنك المتابعة لاحقًا دون إعادة ترجمة الصفحات المكتملة.

## طريقة العمل

```text
صورة الصفحة
   ↓
كشف مناطق النص (Comic Text Detector أو RT-DETR)
   ↓
OCR محلي (PP-OCR الياباني/الإنجليزي) — بلا API
   ↓
تجميع الفقرات في دفعات Smart Batch (معرّفات ثابتة)
   ↓
ترجمة نصية فقط عبر Gemini (أو Vision اختياري)
   ↓
ذاكرة IndexedDB + حفظ المشروع بعد كل دفعة
   ↓
تنظيف النص الأصلي (LaMa أو المسار السريع)
   ↓
رسم الترجمة العربية على الصفحة + إنشاء طبقة نص شفافة
   ↓
توليد PSD عبر ag-psd
```

- الكشف الافتراضي: **Comic Text Detector** (أدق في النص الياباني والفقاعات).
- بديل أخف: **RT-DETR** (~11 MB).
- التنظيف الافتراضي: **LaMa** (جودة أعلى)، مع مسار سريع بدون موديل إضافي.
  المسار السريع مناسب للمعاينة فقط؛ قد يترك آثارًا فاتحة داخل الفقاعات الداكنة.
  استخدم **LaMa** للصفحات النهائية.
- OCR يعمل قبل الترجمة؛ إذا لم يُستخرج نص من صندوق يبقى الصندوق في PSD بلا ترجمة
  ويُمكن تصديره. لا تتحول الصفحة إلى Vision تلقائيًا.

## محرر الصناديق اليدوي

بعد تحليل الصفحة، اضغط **تحرير الصناديق** في رأس لوحة المعاينة. تعمل الأداة على
الصورة الأصلية وتستخدم إحداثيات الصفحة الحقيقية، لذلك تنتقل التعديلات إلى المعاينة
وPSD مباشرة.

- **إضافة صندوق:** اسحب على مساحة فارغة من الصورة. يجب أن يكون الصندوق أكبر من
  الحد الأدنى حتى يُضاف.
- **تحديد:** انقر على صندوق في الصورة أو على صفّه في جدول النصوص.
- **تحريك:** اسحب الصندوق المحدد، أو استخدم الأسهم (Shift + سهم لخطوة أكبر).
- **تغيير الحجم:** اسحب أحد المقابض الثمانية.
- **حذف:** زر **حذف المحدد** أو مفتاح `Delete` / `Backspace`.
- **إلغاء التحديد:** `Esc` مرة، و`Esc` مرة أخرى للخروج من وضع التحرير.
- **تحرير النص:** حقول النص الأصلي والترجمة في الجدول قابلة للتعديل. استخدم
  **ترجمة المناطق الحالية** لإعادة ترجمة الصناديق الحالية دون إعادة الكشف.
  هذا الخيار يستبدل الترجمات الحالية، بما فيها التعديلات اليدوية، بعد تأكيدك.

الصناديق اليدوية تُعلَّم بنمط متقطع وبكلمة «يدوي»، وتُحفظ مع المشروع. لا يوجد حتى
الآن تحديد متعدد أو دمج/تقسيم صناديق؛ كرر الإضافة/الحذف يدويًا عند الحاجة.

## المشروع والحفظ التلقائي

- تُحفظ الصفحات المصدر، والصناديق، والنصوص الأصلية، والترجمات، وإعدادات المشروع
  غير الحساسة في **IndexedDB** داخل المتصفح تلقائيًا بعد التعديلات.
- **حفظ الآن** يكتب نسخة فورية في IndexedDB. حالة الحفظ تظهر في شريط **المشروع**
  أعلى الصفحة.
- **تصدير المشروع** ينشئ ملف `.mpsproj` (ZIP) يحتوي `project.json` وصور الصفحات.
- **استيراد مشروع** يستبدل الصفحات الحالية بعد تأكيدك. تُطبَّق إعدادات المشروع
  غير الحساسة، وتبقى مفاتيح API الحالية في متصفحك دون تغيير.
- لا يضمّ ملف المشروع **مفاتيح API** ولا **ملفات الخطوط المخصصة** ولا **ملفات PSD/PNG
  الناتجة**. أعد تركيب الصفحات بعد الاستيراد/الاستئناف لإنشاء PSD جديد.
- إذا كان المشروع يستخدم خطًا مخصصًا غير موجود في المتصفح الحالي، فسيُستخدم الخط
  الافتراضي مع تنبيه. صدّر ملف الخط من قسم **خطوط مخصصة** وثبّته/أضفه على الجهاز الآخر.
- مسح بيانات الموقع في المتصفح يحذف المشروع المحفوظ تلقائيًا. استخدم التصدير
  للاحتفاظ بنسخة مستقلة.
- فتح المشروع نفسه في نافذتين قد يؤدي إلى آخر حفظ يفوز؛ استخدم نافذة واحدة أثناء
  التحرير.

## ملاحظات PSD المهمة

- كل فقاعة مترجمة تصبح **طبقة نص قابلة للتعديل** باسم `Bubble 001 — editable`.
- الخلفية المنظفة طبقة منفصلة باسم `Background — cleaned page`.
- عند تفعيل **طبقة المعاينة النقطية للعربية** (الافتراضي):
  - تظهر طبقة `Preview — raster Arabic text` بالعربية المشكَّلة كما رسمها المتصفح.
  - تظل طبقات النص القابلة للتعديل **ظاهرة** أسفلها، ومزوّدة بصورة نقطية للطبقة
    حتى لا تظهر فارغة قبل تحديث Photoshop.
  - أخفِ طبقة المعاينة (`Preview`) من لوحة الطبقات عندما تريد رؤية النص الحي وتعديله.
- ملف PSD يخزّن **اسم الخط** فقط، ولا يضمّن ملف الخط. ثبّت الخط المختار على الجهاز
  الذي سيفتح الملف، وإلا سيستبدله Photoshop.
- PSD بدقة 72 PPI، بحيث تساوي البكسل نقطة تقريبًا.
- عند فتح الملف قد يعرض Photoshop تنبيه تحديث طبقات النص. هذا متوقع لأن `ag-psd`
  يكتب بيانات النص لكنه لا يعيد رسم الصورة النقطية للطبقة. اختر تحديث/Update.
  الصورة النقطية المضمّنة في الطبقة تجعل النص ظاهرًا حتى قبل الضغط على Update.
- للعربية داخل Photoshop:
  - فعّل محرك النص الشرقي/World-Ready إن لم يكن مفعّلًا.
  - إذا ظهر النص معكوسًا أو غير متصل، جرّب تعطيل **RTL** في الإعدادات وإعادة التركيب.
  - إذا فشل تشكيل العربية في طبقة النص، استخدم طبقة المعاينة النقطية كنسخة بصرية
    مضمونة، وعدّل النص في طبقة `editable` عند الحاجة.
- موضع النص داخل PSD محسوب ليطابق المعاينة، لكنه قد يحتاج تعديلًا بسيطًا بعد تركيب
  الخط الفعلي. راجع أول صفحة دائمًا قبل تصدير دفعة كاملة.

## الخطوط

الخطوط المضمّنة في `public/fonts`:

| الخط | ملف | ترخيص |
|---|---|---|
| Noto Naskh Arabic | `NotoNaskhArabic-Regular.ttf` | OFL-1.1 |
| Noto Sans Arabic | `NotoSansArabic-Regular.ttf` | OFL-1.1 |
| Amiri | `Amiri-Regular.ttf` | OFL-1.1 |

- يمكن تنزيل الخط من داخل لوحة الإعدادات، ثم تثبيته على Windows:
  انقر بزر الفأرة الأيمن على الملف → **Install** (أو Install for all users).
- أعد تشغيل Photoshop بعد تثبيت الخط.
- نسخ تراخيص OFL موجودة في `licenses/fonts/`.
- إذا اخترت **خط النظام العربي**، فسيعتمد PSD على `SegoeUI` أو الخط المتاح؛ النتيجة
  تختلف بين الأجهزة.

### خطوط مخصصة

- من الإعدادات → **خطوط مخصصة** اضغط **إضافة خط** واختر ملف
  `TTF` أو `OTF` أو `WOFF` أو `WOFF2`.
- يقرأ التطبيق اسم PostScript تلقائيًا، ويضيف الخط إلى قائمة الخطوط ويختاره مباشرة.
- يُحفظ ملف الخط في **IndexedDB داخل هذا المتصفح فقط**، ولا يُرفع إلى أي خادم.
- يمكنك تنزيل ملف الخط من بطاقة الخط المخصص لتثبيته على جهازك.
- ملف PSD يخزّن **اسم PostScript فقط**؛ يجب تثبيت الخط على الجهاز الذي سيفتح PSD
  حتى يظهر النص بنفس الشكل. إذا لم يكن الخط مثبتًا، قد يستبدله Photoshop بخط آخر.
- حذف الخط من قائمة الخطوط المخصصة يحذفه من تخزين المتصفح، لكنه لا يحذف نسخة
  PSD أو نسخة الخط المثبتة على نظامك.
- الخطوط المخصصة مسؤولية المستخدم من حيث الترخيص؛ لا ترفع خطًا تجاريًا لا تملك
  حق استخدامه أو إعادة توزيعه.

## الأمان والخصوصية

- لا يوجد خادم خلفي لهذا التطبيق ولا تتبع ولا تحليلات.
- الصور تبقى في الذاكرة المحلية (Blob URLs) ولا تُرسل إلا إلى مزود الترجمة المختار.
- في الوضع اليدوي لا تُرسل الصور إلى أي خدمة.
- المشروع (الصور والصناديق والنصوص) يُحفظ في IndexedDB داخل المتصفح. لا يغادر
  جهازك إلا إذا صدّرته بنفسك أو أرسلت الصور إلى مزود الترجمة.
- مفاتيح API تُحفظ في `localStorage` ولا تُضمّن في ملفات المشروع. هذا مناسب لجهاز
  شخصي، وليس لاستضافة عامة.
- لا تضع مفاتيح حقيقية في مستودع Git أو في نسخة منشورة للعامة.
- استخدم مفتاحًا بصلاحيات محدودة، وراقب الاستخدام من لوحة المزود.

## الاختبار والتطوير

```bash
npm test          # اختبارات الوحدة: Smart Batch، الذاكرة، مدير الطلبات
npm run check     # TypeScript
npm run build     # إنتاج dist/
```

تم اختبار المسار التالي أثناء التطوير:

- Comic Text Detector + OCR إنجليزي محلي على صفحة تجريبية → 2 فقرات، ثم ترجمة
  16 فقاعة في 8 صفحات باستخدام **طلبين فقط** (4 صفحات/دفعة).
- طلب نصي فقط: تم التأكد من عدم وجود `inlineData` أو Base64 في جسم الطلب.
- ترتيب رد Gemini مبعثرًا: تم ربط الترجمات بالمعرّفات `p001_b001` … بدل الترتيب.
- JSON غير صالح → إعادة محاولة بدون `responseSchema` ثم النجاح.
- 429 مع `Retry-After` → إعادة المحاولة ونجاح الطلب نفسه.
- استنفاد الحصة اليومية → توقف مؤقت دون تدوير مفاتيح.
- انقطاع الشبكة → إعادة محاولة ثم توقف مع حفظ الصفحات المكتملة.
- إيقاف يدوي أثناء الطلب → `AbortError` وحفظ الحالة.
- ذاكرة IndexedDB: تشغيل ثانٍ لنفس النص → **0 طلبات** وإصابة ذاكرة.
- تعديل فقاعة واحدة → مفتاح ذاكرة مستقل، ولا تُلغى بقية الترجمات.
- 30 صفحة × 18 فقاعة في اختبارات الوحدة → 8 دفعات، 540 معرّفًا، بلا فقد.
- فشل OCR مع صندوق بلا ترجمة → ما زال PSD صالحًا للتصدير (طبقة نص فارغة).
- الحفظ التلقائي والاستئناف، وتصدير/استيراد `.mpsproj` دون مفاتيح API.
- محرر الصناديق: إضافة/تحريك/تغيير حجم/حذف صندوق يدوي، وتحديث الترجمة، ثم PSD.
- قراءة PSD مرة أخرى باستخدام `ag-psd` للتأكد من وجود طبقات النص والخط والاتجاه.

لتشغيل خادم Gemini وهمي بدون مفتاح حقيقي:

```bash
PORT=8788 node scripts/mock-gemini.mjs
```

ثم في الإعدادات:

- المحرك: Gemini — OCR محلي + ترجمة نصية
- Base URL: `http://127.0.0.1:8788/v1beta`
- Model: `mock-gemini`
- API key: أي نص غير فارغ، مثل `mock-key`

نماذج السيناريو: `mock-missing`، `mock-malformed`، `mock-429-once`،
`mock-429-daily`، `mock-offline`. هذا الخادم للاختبار فقط.

لتشغيل خادم OpenAI-compatible الوهمي القديم:

```bash
node scripts/mock-openai.mjs
```

ثم: Base URL `http://127.0.0.1:8787/v1`، Model `mock-vl`، API key فارغ.

## القيود الحالية

- OCR الإنجليزي والياباني الأفقي تم اختبارهما محليًا. جودة OCR الياباني العمودي
  تعتمد على وضوح الخط؛ لم يتوفر في بيئة التطوير نموذج مانجا ياباني عمودي موثوق
  للتحقق البصري النهائي. راجع النص المستخرج قبل التصدير، وفعّل Vision للفشل فقط
  عند الحاجة.
- لا يدعم PDF أو ملفات CBZ مباشرة؛ أضف صور الصفحات.
- لا يوجد تراجع/Undo شامل داخل الجدول أو محرر الصناديق.
- محرر الصناديق يدعم حاليًا الإضافة/التحريك/تغيير الحجم/الحذف، دون تحديد متعدد
  أو دمج/تقسيم صناديق.
- الحفظ التلقائي محلي لهذا المتصفح فقط، وليس مزامنة سحابية. ملفات PSD الناتجة
  لا تُحفظ في المشروع؛ تُعاد باستخدام **تركيب وتحديث PSD**.
- جودة الكشف تعتمد على وضوح الصفحة ونوع المانجا. راجع دائمًا الصفحات قبل التصدير.
- تشكيل العربية داخل PSD يعتمد على محرك النص في Photoshop/المحرر. طبقة المعاينة
  النقطية هي الضمان البصري، وطبقات النص هي نسخة التعديل.
- لم يتم التحقق من PSD داخل Photoshop أو Photopea في بيئة التطوير الحالية؛ تم التحقق
  من بنية الملف وطبقاته عبر `ag-psd`. اختبر أول ملف على جهازك قبل دفعة كبيرة.
- مسار Gemini النصي وVision تم اختبارهما بخادم وهمي متوافق. لم يتوفر مفتاح API
  حقيقي في بيئة التطوير، لذا راجع أول طلب حقيقي من لوحة استخدام Google.
